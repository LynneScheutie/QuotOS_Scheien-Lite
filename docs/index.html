from transformers import AutoModelForCausalLM, AutoTokenizer

model = AutoModelForCausalLM.from_pretrained("./QuotOS_Scheien-Lite-fp16", dtype="float32")
tok = AutoTokenizer.from_pretrained("./QuotOS_Scheien-Lite-fp16")
msg = [{"role": "user", "content": "试用期被辞退，公司没给理由，怎么办？"}]
ids = tok.apply_chat_template(msg, add_generation_prompt=True, return_tensors="pt")
out = model.generate(ids, max_new_tokens=600, do_sample=False)
print(tok.decode(out[0][ids.shape[1]:], skip_special_tokens=True))

能力边界

这是验证件，不是产品它学会了回答的结构与边界，没有学会法。下面的几条是实测结论，不是客套话。

结构学会了，条文会讲错。五段式结构、免责声明、越界拒答都学到了，免责声明出现率从基座的 50% 提到 100%。但训练门禁只校验「这部法有没有这一条」，不校验条文有没有被曲解。GGUF 实测里它把降职降薪的依据安到了《劳动法》第三十条上，正确依据应是《劳动合同法》第三十五条。

编造条号为零，不等于引用正确。门禁把编造条号压到了 0，可释义张冠李戴的情况仍然存在。任何引用都要回法条库核对原文，把当起草助手用，别当法条查询器。

0.6B 装不下法条全文。这个参数量硬背条文必然走形。设计上就是「模型学怎么说，法条库管说什么」——条文原文要外部检索注入。

不做的事。刑事、涉外、税务、诉讼策略都在边界外，遇到会明确转介；输出不构成法律意见，不能替代执业律师。

常见问题

为什么不做 4B

4B 是另一条线（MLX / QLoRA / 云端），在自己的独立仓库里跑，和这一版互不混用。这一页只负责 0.6B。

会不会编条号

训练数据全部过了条号门禁，实测编造条号率为 0。但门禁不校验释义，条文讲错的情况确实存在，引用前请回库核对。

能不能当法条查询器

不能。它记不住条文原文，也不该记。查条文请用检索库或官方数据库，这个模型只负责把条文讲成人话。

能不能商用

代码与法条数据 Apache-2.0，基底 Qwen3-0.6B 亦为 Apache-2.0。但模型输出不构成法律意见，商用场景请自行评估并配备人工复核。

手机上能跑吗

GGUF 378 MB，llama.cpp 的移动端构建可以加载，速度取决于机型。没有移动端专用版本，也没有做适配测试。
