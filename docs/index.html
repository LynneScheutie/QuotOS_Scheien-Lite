ollama run scheien-lite

回答结构固定：①结论 ②法律依据（法律名称+条号+条文要点，最多3条）

想让她用夏依恩的口吻说话，把上面 SYSTEM 换成 Lawlearn 的 scheien 人设即可——模型本身只会这一套标准口径，不会自动变成她。提问末尾加 /no_think 可跳过模型偶尔冒出来的思考段，直接给结论。

纯 llama.cpp 的命令行写法、必须知道的缺陷清单：USAGE-zh.txt。

为什么是獬豸

名字不是随便取的，她也不是贴上去的吉祥物。

獬豸能辨曲直

传说中它能用角顶倒理亏的一方。这个模型的全部克制都来自同一个动作：只引用库里校验得到的条号，不合规的直接判掉——训练数据的门禁就是这么干活的。

洁癖式的严谨

她挑标点、挑格式，对应到模型上就是固定五段式输出：结论、依据、要件套用、风险时效、免责声明。少一节就算不合格，评测里算「结构不完整」。

能力边界

下面几条不是客套话，是实测出来的，写在模型卡里。

会的是壳子，不是法。五段式结构、免责声明、越界拒答都学会了；免责声明率从基底的 50% 提到 100%。

条号能对上，条文会讲错。训练门禁只校验「这部法有没有这一条」，不校验条文内容有没有被曲解。所以「编造条号 = 0」是假安全。GGUF 实测里它把降职降薪的依据安到了《劳动法》第三十条上——正确依据应是《劳动合同法》第三十五条。

任何引用都要回法条库核对。当起草助手，不要当法条查询器。0.6B 装不下法条全文，硬背必然走形。

它是怎么来的

全部在一个桌面工作目录里跑完，没有云 GPU。

训练

Qwen3-0.6B + LoRA SFT（r=16 / α=32，可训 1.66% 参数）。Windows 笔记本纯 CPU，8 线程，180 步分 6 段，约 72 分钟。

选模

按验证集 loss 挑：60 步见底 1.0694，之后 1.08 → 1.17 → 1.26 → 1.44 一路上升，180 步已经过拟合。所以默认版本锁在 step_00060。
